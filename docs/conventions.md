# Conventions

How code, schema changes and docs are written in this repo. `CLAUDE.md` at the repo root is the source these rules come from. If the two disagree, `CLAUDE.md` wins, and this note should be fixed.

**Related:** [[00-index]] · [[architecture]] · [[data-layer]]

## Code

- Path alias `@/*` → `src/*`.
- Prettier: single quotes, semicolons, print width 100. Imports and Tailwind classes are sorted by plugins, so don't order them by hand.
- Husky pre-commit runs `lint-staged`: `eslint --fix` on `*.ts(x)`, `prettier --write` on `js, jsx, json, css, md` (so these notes get formatted too).
- `src/components/ui/map.tsx` is vendored (mapcn) and excluded from lint. Leave it alone.
- The Prisma client is generated by `npx prisma generate` (also on `postinstall`). The generator sets no `output`, so the client lands in `node_modules` and is imported from `@prisma/client`. `CLAUDE.md` still says `src/generated/`, which doesn't exist.
- Forms: Zod schemas in `src/lib/schemas.ts`, `react-hook-form` + `@hookform/resolvers`.
- One hook file per domain in `src/components/hooks/`. Mutations invalidate query keys on success (see `use-events.ts`).
- New lookup tables extend `LOOKUPS` / `LookupTable`, not a new CRUD page ([[0009-table-driven-settings]]).
- Admin queries take the scoped campus id from `useScopedCampusId`. Don't add per-page campus filters ([[campus-scoping]]).
- New server actions that need to know the caller verify the Supabase token (`requireProfile` / `requireAdmin`) instead of trusting an id from the client ([[0007-token-verified-actions]]). Expected failures return `{ ok: false, error, retry }` and are not thrown.

## Theme

Colours are tokens in `globals.css` that switch under `.dark`, so `text-gray-600` needs no `dark:` variant. Use `bg-canvas` for pages, `bg-surface` (not `bg-white`) for cards, bars, drawers and inputs, `border-line` for hairlines, and `bg-brand-solid` for maroon fills with white text. `data-theme="light"` keeps a subtree light (A4 reports). See [[design-system]].

## Database

- Schema changes ship as **idempotent SQL in `prisma/manual/<ticket>.sql`** plus the matching `schema.prisma` edit ([[0002-manual-sql-schema-changes]]).
- **Never run** `npx prisma db push`, `npx prisma migrate dev`, `npx prisma migrate reset`.
- Apply a manual file over the direct connection (the pooler on :6543 hangs on `db execute`):

  ```bash
  DATABASE_URL="$(grep -E '^DIRECT_URL=' .env.development.local | cut -d= -f2- | tr -d '"')" \
    node --env-file=.env.development.local node_modules/prisma/build/index.js db execute --file prisma/manual/<file>.sql
  ```

- Models are PascalCase with snake_case tables and columns (`@map` / `@@map`). IDs are `gen_random_uuid()`.
- `npm run seed` seeds lookups, and `npm run seed:matatag` seeds the checklist (idempotent, matches by code, never deletes).

## Verify before calling it done

```bash
npm run lint && npm run type-check && npm run test && npm run build
```

Test accounts for the browser are in `test-accounts.local.md` at the repo root. It is gitignored, so never copy it into the docs.

## Docs (this vault)

- **Where:** plans in `plan/{feature,fix,bugs,review}/`, one note per area of code in `modules/`, one note per decision in `decisions/`. Start new docs from the `TEMPLATE.md` in each folder.
- **Names:** kebab-case with a ticket or date prefix, e.g. `plan/fix/DRRM-003-report-form-atomicity.md`, `plan/review/2026-09-08-dev-branch-audit.md`, `decisions/0004-offline-queue-bundled-create.md`.
- **Branches map 1:1 to plans:** `feat/DRRM-015-...` ↔ `plan/feature/DRRM-015-...`.
- **Plan frontmatter** (all plans and templates have it):

  ```yaml
  ---
  type: feature # feature | fix | bug | review
  ticket: DRRM-015
  status: in-progress # draft | in-review | approved | in-progress | done
  branch: feat/DRRM-015-assessment-form
  modules:
    - '[[assessments]]'
    - '[[offline-pwa]]'
  tags: [plan, feature]
  ---
  ```

  Keep the `- **Status:** ...` line in the body too, since CLAUDE.md requires it. When the status changes, update both.

- **Links:** plans link to modules through `modules:`. Module notes don't list their plans, because Obsidian's Backlinks pane shows them. In note bodies use `[[wikilinks]]`. Links to source files use relative Markdown links (`[x](../../../src/lib/x.ts)`) so they also work on GitHub. Never use `file:///` links. The four `TEMPLATE.md` files share a name, so link them by path: `[[plan/fix/TEMPLATE]]`.
- **When a decision is made**, add `decisions/NNNN-slug.md` from [[decisions/TEMPLATE]] and link it from the module notes it affects.
- **When a ticket merges**, add a line to [[changelog]] and set the plan's status to `done`.
